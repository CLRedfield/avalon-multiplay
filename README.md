# Avalon Multiplay

浏览器多人阿瓦隆。项目是纯静态页面，不需要 Firebase、腾讯云或自建数据库；联机通过公共 MQTT WebSocket Broker 转发房间消息，由房主浏览器串行处理游戏状态。

## 本地运行

在项目目录启动任意静态文件服务器，例如：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

然后打开 <http://127.0.0.1:8000/>。同一房间的玩家必须选择同一个联机服务器。

## 玩法工坊

大厅默认使用“现有玩法”，也可以选择轻量推理、迷雾身份、圆桌议会、中立博弈、混沌盛宴。每套模板都包含独立的 5—10 人配方；大厅人数变化后会自动使用对应配方。

房主点击“编辑 / 另存模板”可以修改角色名额、中立随机席位和候选池、五场任务人数与失败门槛、放逐限制、连续否决上限、刺杀开关、事件池和抽牌场次。错误配置不能应用或保存。特殊角色最多一名，随机中立不会重复抽到固定中立；关闭放逐或限制放逐次数时，依靠放逐取胜的身份需要足够的放逐机会。

“应用到房间”同步全员可见的配置，不自动保存到本机；“保存到本机”保留个人模板，可通过名称修改和“复制模板”管理。JSON 导入导出用于备份、分享，最多保存 50 套模板。本机存储不可用时仍可编辑、应用和导出。对局开始时冻结完整配方，对局中不能修改。

模板 JSON 的 `version` 当前为 `1`；`variants` 包含 `5` 至 `10` 六个人数键。每个配方包括 `playerCount`、`roleCounts`、`neutralSlots`、`neutralPool`、`missionSizes`、`missionFails`、`exileEnabled`、`maxExiles`（`null` 表示不限）、`rejectionLimit`、`assassinationEnabled`、`eventPool` 和五项布尔数组 `eventRounds`。请通过工坊导出完整文件作为编辑起点；不兼容版本和非法数据会被拒绝。预设和校验集中在 `js/rules-config.js`。

## 新角色与技能

新增见证者、密探、守誓者、隐士、幻术师、黑卫、赌徒、赏金客，共 19 种角色。角色及事件图鉴可在首页、大厅和对局中打开。

- 见证者查上一场两名其他队员是否至少一人提交失败牌；密探查两名其他玩家是否同阵营。查验均每局一次，只读真实记录。
- 守誓者和黑卫每局一次保护一名其他玩家，抵消本场任务完成前的第一次成功放逐；同一目标的保护不叠加，保护来源不公开。放逐被抵消后仍轮换队长，不增加放逐次数或任务场次。
- 隐士不被梅林看见，但与其他坏人正常互认；幻术师出现在派西维尔的候选名单中。奥伯伦仍沿用本项目原有规则。
- 赌徒默认预测前三场实际任务为“成功 / 失败 / 成功”，可在首次窗口修改；三场全部命中且未出局时立即获胜。赏金客开局获得两个不同的秘密目标，二人均被放逐且自己仍在场时立即获胜。两种新中立只能提交成功牌。

配置包含新主动能力时，任务开始前进入最多 20 秒的秘密技能窗口。所有在场玩家提交技能或跳过，收齐提前结束；超时跳过不消耗能力。技能内容（包括使用或跳过）、结果与秘密目标均通过加密通道传递。掉线恢复会补发当前私密状态，重复请求不会重复消耗技能。角色阵营整局固定。

中立即时胜利先于同一结算点的阵营胜利；多个中立同时达标时共同获胜。原有中立的能力保留，默认模板仍只包含一个随机中立席位。

## 事件与复盘

策略池包含重整编队、圆桌轮值、暂缓放逐、审慎表决；混沌池包含临时增援、守护屏障、单点危机、双倍战果。可单独选池、混搭或逐张选择，每场最多抽一张，默认五场都抽。

房主私下保存洗牌后的牌堆，只公开当前抽到的事件。抽取不放回，牌堆耗尽后重洗；当前剩余牌均不适用时本场没有事件。否决、放逐或断线重组队伍不会重新抽牌。重整编队因永久离场而无法满足时会公开撤销限制。

任务开始时冻结队伍人数、失败门槛和进度权重。双倍战果计两点进度，累计三点触发阵营胜利或刺杀，但任务场次只增加一场；赌徒、军火商仍按真实场次判断。永久离场或放逐造成队伍不足时按剩余人数收缩，临时断线不收缩。

顶部“我的情报”保存个人夜间信息、技能结果、预测和赏金目标。“时间线 / 复盘”在进行中仅展示公共事件、提案、投票结论、任务成败和放逐；正常终局后公开身份、真实任务牌、技能和秘密目标。安全中止不会猜测或公开缺失记录。

新增预设是实验玩法，自动化测试验证规则与同步，不代表已经完成真人胜率平衡。建议先按模板试玩，再调整各人数配方。

## 玩家顺序与选人

玩家列表统一按大厅的入房顺序显示。新对局保持此座次轮换队长，首位队长和身份分配仍随机。

队长组队和选择放逐目标时，点击只更新本地草稿，不逐次发送网络请求；确认后一次性提交完整提案并进入投票。提交期间不能重复确认，失败后保留草稿供重试；掉线、离场或被放逐的目标会从草稿中移除。刷新页面会清空尚未提交的选择。

## 公共联机服务器

默认服务器：

```text
wss://broker.emqx.io:8084/mqtt
```

界面也可以切换到 `broker-cn.emqx.io`、HiveMQ 或 Mosquitto 测试服务器。配置位于 `js/mqtt-config.js`。

应用层会为玩家指令和房间快照签名，身份、夜间信息与任务牌使用每位玩家的独立密钥加密；普通玩家不能再直接篡改整局状态。

公共 Broker 仍只适合朋友间临时游玩和测试：它不保证服务可用性，也没有服务端房间 ACL。首次接触某个房间时仍需要信任 Broker 返回的首个有效快照，房主浏览器也是本局的可信权威。不要在昵称或房间里放敏感信息。

## 掉线恢复与延迟

- MQTT 断线后每 750 ms 尝试重连，网络恢复、页面重新显示时立即尝试恢复。重新订阅后向房主确认最新状态并补发加密身份、技能结果；同步完成前不接受新游戏操作。
- 每 5 秒发送轻量签名心跳（不增加房间版本），20 秒没有心跳进入失联判断，MQTT 遗嘱可更早触发。确认失联后普通玩家保留 15 秒，对局中的房主保留 60 秒。宽限期内保留队长、投票资格和已提交任务牌；恢复后继续原局。大厅房主使用 15 秒宽限期。
- 提交立即发送，未收到确认时以同一请求编号退避重发，最长等待 75 秒。房主串行执行并保存最近 256 个结果，确认丢失或房主刷新不会重复执行同一提交。每条游戏指令绑定对局、阶段、任务和选人轮次，过期指令不能落到下一轮。
- 房主每次提交将公开状态、秘密任务牌和去重记录一起保存到本机检查点。房主刷新、公共 Broker 丢失保留消息时，可由原房主的检查点恢复。响应和私密消息均验证签名，身份仍只加密发送给本人。
- 房主自身操作直接进入同一权威队列，省去请求的网络往返；心跳与响应不等待游戏指令队列。选人草稿、个人标记立即在本地更新，心跳不反复广播整局状态。
- 对局顶部显示连接、同步、等待房主及转发往返时间，并提供“立即重连”。这里的毫秒数是客户端到转发服务器再返回的时间，实际操作还包括玩家到房主的链路与处理时间。
- 支持 Web Locks 的浏览器会阻止同一玩家在同一站点的多个标签页同时连接，避免两个房主页面同时写入。

原房主超过宽限期仍未恢复时，下一位在线玩家接任并安全中止本局，可返回大厅重开。其他玩家不持有原房主的秘密分配，不能无损接管正在进行的对局。浏览器清除存储、系统冻结后台页面、所有客户端同时关闭或公共 Broker 长期不可用，仍无法保证恢复；房主应保持页面运行。

要获得房主关页也不中断、跨设备恢复与稳定低延迟，需要部署靠近玩家的常驻权威服务，将房间状态、秘密身份、动作日志和重连令牌保存在服务端，并使用受认证的 WebSocket 通道。当前纯静态架构不能提供这一保证。MQTT 参数依据 [MQTT.js 官方文档](https://github.com/mqttjs/MQTT.js#client)。

本次协议使用独立的 `avalon-multiplay/v5` 频道（协议版本 3），会话、房主秘密和检查点也使用独立的 v5 存储键。所有玩家需刷新到同一版本并新建房间；不会读取旧版对局恢复记录，旧记录本身保留。对局中不会自动切换公共服务器，避免同一房间分裂到不同服务器。

## 个人标记

点击玩家卡片的“＋ 标记”，或任意对局阶段顶部的“我的标记”，可以分别记录具体身份和“好人 / 疑似坏人 / 坏人”。修改即时生效，可以单独取消，也可以清空本局标记。

标记只写入当前浏览器，不进入房间快照、指令或私密频道；按联机服务器、房间、本人和对局隔离。刷新或重连保留本局标记，新对局从空白开始。离线、放逐、离场玩家仍可标记；本地存储不可用时页面会提示标记仅在本次打开期间有效。

## 测试

```powershell
node --test tests/*.test.js
```

测试覆盖标准任务规则、9/10 人角色分布、中立角色胜利、放逐轮次、连续否决、昵称转义、MQTT 多客户端同步、并发动作重试、权限验证、私密消息加密、房主掉线接任及保留房间清理。

选人回归测试还覆盖入房顺序、本地点选、一次性提交、防重复确认、提交失败重试、掉线目标清理与过期提案拒绝。

扩展测试包含六套预设 × 六种人数的完整规则对局、技能冲突、事件、同时胜利、JSON 和私密信息边界，并使用 5、7、10 个独立 MQTT 客户端完成模板同步、并发投票、加密技能、丢失回执重试、重连和终局复盘。7 人场景还覆盖技能提交后房主刷新恢复。并发写入允许最多 16 次版本冲突重试，以支持满员同时准备或投票。

本地界面验收入口为 <http://127.0.0.1:8000/tests/browser-smoke.html>，可切换 5、7、10 人技能和复盘场景。它复用真实页面、界面代码与技能处理器，玩家和存储仅存在于测试 iframe 内存中，不连接公共 MQTT。此入口只用于界面验收，联机验证使用上述自动化测试。
